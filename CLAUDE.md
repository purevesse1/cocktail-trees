# Notes for Claude Code

Project: Cocktail Trees, static site, one radial tree per base spirit. See README.md for layout.

Design rules
- Strict black and white, light/dark aware via CSS vars in index.html. Fonts: Archivo (display), IBM Plex Mono (labels).
- Box filled black = every ingredient is in My bar; white = something missing.
- Diff labels: "+ dry vermouth", "− sugar syrup" (space after sign; real minus sign). Subtractions only where a sweetener is swapped.

Interaction (js/tree.js)
- Click a drink: box expands into a recipe card; neighbours pushed aside by hand-written spring + rectangle-collision physics;
  hub→drink path highlighted thick, other boxes kept off that line. One card open at a time.
- Camera: free transform. Wheel = eased zoom at cursor (1×–16×). Middle-hold or left-drag pans; touch pan + pinch.
  Soft rubber-band boundary (`lim()`, `rub()`), springs back on release. Fit button recentres.
- Keep the hand-written physics (WebCola / d3-force were considered and rejected for now).

Data
- Shared steps: `S(["+ pineapple juice"], [...])` in gen.py makes a dashed pill (node with `step:1`) that several drinks branch from. It is not a drink: no recipe, no click, not counted. Use one only when 2+ sibling drinks share an added ingredient and no real drink fills that spot.
- data/<base>.js is generated by tools/gen.py; don't hand-edit layout coordinates. Recipe ingredients must match the tree's cumulative ingredients (gen.py asserts this).

Working style
- Direct, technically precise; no unexplained jargon.
- Test in a browser via `python -m http.server`; there is no build step and no dependencies.
